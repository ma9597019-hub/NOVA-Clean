# تتبّع المشروع — Vercel + Supabase

## الملفات
- `index.html` — الموقع (التصميم والوظائف كما هي) مع طبقة Supabase الجديدة.
- `api/login.js` — جسر الدخول: يتحقق من كلمة السر القديمة (SHA-256 كما هي) ثم يُنشئ **جلسة Supabase Auth حقيقية**.
- `api/config.js` — يعيد URL والمفتاح العام فقط.
- `api/analyze.js` — فحص الصور بالذكاء الاصطناعي (المفتاح على الخادم فقط).
- `api/_users.js` — هاشات كلمات السر الحالية (نفس الموجودة في الصفحة الأصلية).
- `supabase/setup.sql` — الـ bucket الخاص + سياسات Storage + جدول البيانات + RLS.

## خطوات التشغيل
1. Supabase → SQL Editor → الصق `supabase/setup.sql` ونفّذه.
2. Vercel → Project → Settings → Environment Variables:

| المتغير | القيمة | ملاحظات |
|---|---|---|
| `SUPABASE_URL` | `https://xxxx.supabase.co` | Project Settings → API |
| `SUPABASE_PUBLISHABLE_KEY` | المفتاح العام (publishable / anon) | يصل للمتصفح عبر `/api/config` |
| `SUPABASE_SECRET_KEY` | المفتاح السري (service_role) | **خادم فقط**، لا يُستخدم إلا في `api/login.js` |
| `AUTH_BRIDGE_SECRET` | نص عشوائي طويل (32+ حرفًا) | يشتق كلمات سر حسابات Supabase الداخلية؛ **لا تغيّره بعد الإطلاق** |
| `ANTHROPIC_API_KEY` | مفتاح Anthropic | لفحص الصور؛ بدونه لا يُعتمد أي إثبات |
| `ANTHROPIC_MODEL` | اختياري | الافتراضي `claude-sonnet-5-5` |

3. انشر المشروع (`vercel --prod` أو Git). لا حاجة لخطوة بناء.

## كيف يعمل
- الدخول: الاسم + كلمة السر القديمة → `/api/login` → جلسة Supabase (JWT فيه `app_metadata.slug/role/member` يضعها الخادم فقط).
- الرفع: `project-images/<slug>/<category>/<uuid>.jpg` حيث category = `components` أو `invoices` أو `updates`. (الـ slug هو بصمة قصيرة لاسم المستخدم لأن مفاتيح Storage لا تقبل العربية.)
- العرض: Signed URLs لساعة واحدة، تُخزَّن مؤقتًا وتُجدَّد تلقائيًا قبل الانتهاء أو عند فشل تحميل الصورة.
- الحذف: يحذف الصورة من Storage أولًا (والسياسة تتحقق من الملكية/المالك)، ثم السجل.
- لا يوجد `getPublicUrl` ولا Base64 في قاعدة البيانات.

## حدود يجب أن تعرفها
- الصور القديمة المخزّنة بمعرّفات `/_blob/` في المنصة السابقة لا تُنقل تلقائيًا؛ تظهر فارغة حتى تُرفع من جديد.
- بيانات المنصة القديمة (db) لم تُنقل؛ الجدول `kv` جديد وسيُزرع بالبنود الافتراضية عند أول دخول.
- قرار «اعتماد الإثبات» ما زال يُتخذ في المتصفح بعد نتيجة الفحص (كما في تصميمك الأصلي)؛ السياسات تحمي الصور والبيانات لكن عضوًا خبيرًا قادر تقنيًا على كتابة حالة بند. للتشدد لاحقًا انقل الاعتماد إلى API.
- الزوار غير المسجلين يرون النصوص لكن لا يرون الصور (Bucket خاص).
